Step 5 of the design challenge workflow. Stage: **Tell** in `framework/HOW-I-THINK.md`.

Read `brief/BRIEF.md`, `output/framing.md`, `output/decision-log.md`, everything in `output/artifacts/`, and screenshots of the prototype.

## Structure (the story, ~15 minutes presented)

1. **The problem as I framed it**: the prompt, my reframe, who it's for. (Frame)
2. **What I learned**: research highlights and the riskiest assumption. (Understand)
3. **My bets**: 3–5 bets and how we'd know. (Bet)
4. **The prototype**: walk the demo script. Link the live prototype. (Make)
5. **The agentic system** (if agentic): risk map, autonomy heatmap, recovery map, guardrails summary. One visual each, one sentence on what to notice. (Make)
6. **How I'd test it**: metrics and the first test. (Test)
7. **Alignment asks**: open decisions for PM and engineering, from the guardrails spec. (Tell)
8. **What I'd do with more time**, and the decisions I made, from the decision log.

Ask Michael which sections to keep for this audience before building. Cut anything thin.

## Build

- `output/readout/index.html` as the story, linking each artifact page in `output/readout/`. Shared `style.css`. Static files only, so it can be hosted on GitHub Pages.
- A `README.md` at the challenge root that reads well on GitHub on its own: summary, links to the readout, prototype and artifacts.
- Optionally a slide version: ask first.

## Share check

Before anything goes public, ask Michael: is the prompt under NDA or marked confidential? Does it include company data? If yes, recommend a private repo shared with specific people, or a public repo with the prompt paraphrased.
